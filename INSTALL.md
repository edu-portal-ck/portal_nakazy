# Реєстр наказів — інструкція встановлення для адміністратора

Від чистого сервера Debian до робочої програми, якою користується вся установа. Займає 30–60 хвилин, більшість часу — автоматичне завантаження пакетів.

Позначки: **[обов'язково]** — без цього програма не працюватиме; **[рекомендовано]** — варто зробити одразу; **[за потреби]** — залежить від вашої мережі.

---

## 0. Що підготувати

| Що | Навіщо |
|---|---|
| Сервер або віртуальна машина: **Debian 13** (мінімальна установка, без графіки), 2 ГБ RAM, 2 ядра, диск — 10 ГБ + місце під ваші скани | тут працюватиме програма |
| **Постійна IP-адреса** сервера в локальній мережі (наприклад, `192.168.1.100`) | за нею працівники відкриватимуть сайт |
| **Інтернет** на сервері під час встановлення | завантажуються Docker, LibreOffice тощо (~1 ГБ) |
| Логін і пароль **звичайного користувача**, створеного під час установки Debian, і **пароль root** | заходити на сервер і виконувати команди від root |
| Комп'ютер адміністратора з Windows: програми **PuTTY** (або вбудований `ssh` у командному рядку) і **WinSCP** | керувати сервером і копіювати на нього файли |
| Архів програми **`nakazy.zip`** | сама програма |

> Постійну IP-адресу найпростіше закріпити на роутері (резервування DHCP за MAC-адресою сервера). Поточну адресу сервера показує команда `hostname -I`.

Під час установки Debian достатньо вибрати «SSH server» і «standard system utilities». Графічне середовище не потрібне.

> **Важливо:** Debian не дозволяє заходити по SSH одразу під `root` з паролем. Тому заходьте під звичайним користувачем (далі в прикладах — `admin`; у вас — той, кого ви створили під час установки), а для команд ставайте root командою `su -` (вона спитає пароль root). Якщо під час установки Debian пароль root не задавали — замість `su -` використовуйте `sudo -i` (спитає пароль вашого користувача).

## 1. Скопіювати архів на сервер [обов'язково]

1. Відкрийте **WinSCP** → новий сеанс: протокол SFTP, адреса сервера, ваш користувач (`admin`) і його пароль → «Увійти».
2. Праворуч відкриється ваша домашня папка на сервері (`/home/admin`). Перетягніть туди `nakazy.zip` зліва.

(Або з командного рядка Windows: `scp nakazy.zip admin@192.168.1.100:`)

## 2. Встановити програму [обов'язково]

Підключіться до сервера (**PuTTY** або в командному рядку Windows `ssh admin@192.168.1.100`), станьте root і перенесіть архів у `/opt`:

```bash
su -
```
(введіть пароль root; запрошення зміниться на `root@…#`)
```bash
mv /home/admin/nakazy.zip /opt/
```
Далі по черзі:
```bash
apt-get update && apt-get install -y unzip
```
```bash
cd /opt && unzip nakazy.zip && cd nakazy && ./install.sh
```

Скрипт сам встановить Docker, збере й запустить програму. **Перший раз це 10–30 хвилин** залежно від швидкості інтернету — це нормально, навіть якщо на якомусь рядку довго немає змін.

Наприкінці з'явиться приблизно таке:
```
Готово. Відкрийте у браузері: http://192.168.1.100
Вхід: «Увійти» -> Адміністратор, пароль: Xk7pQm2RtW9a
(пароль згенеровано й збережено у файлі .env)
Після входу одразу змініть пароль на свій.
```
**Запишіть цей пароль** — він знадобиться для першого входу.

✅ **Перевірка:** на своєму комп'ютері відкрийте в браузері адресу з повідомлення. Має з'явитися сторінка «Реєстр наказів з основної діяльності».

## 3. Перший вхід і зміна пароля [обов'язково]

1. Натисніть **«Увійти»**, оберіть **Адміністратор**, введіть пароль із попереднього кроку.
2. Угорі з'явиться жовта смуга «Ви користуєтесь початковим паролем» → **«Змінити пароль»** → задайте свій (не менше 8 символів).

✅ **Перевірка:** жовта смуга зникла.

## 4. Налаштувати програму під установу [обов'язково]

Усе робиться в браузері, меню **«Адміністрування»** угорі праворуч.

1. **Довідники → Реєстри.** Після встановлення є «Основна діяльність» і один кадровий «Кадрові» із суфіксом «-к».
   - Перейменуйте їх під свою номенклатуру справ (коротка назва — це вкладка, повна — заголовок сторінки), натисніть «Зберегти» в рядку.
   - Якщо кадрових журналів кілька (наприклад, окремо особовий склад, відпустки, відрядження) — додайте їх у верхньому рядку, вид «Кадровий».
   - Суфікси номерів задайте **до** того, як почнете вносити накази.
2. **Довідники → Співробітники.** Додайте людей (верхній рядок → «Додати»):
   - хто готує накази — лише ПІП, без ролей (їх обирають у полі «Хто створив»);
   - хто працює з програмою — поставте галочку ролі й задайте пароль: **Секретар** веде основні накази, **Кадровик** — кадрові, **Переглядач** бачить усе, але нічого не змінює, **Адмін.** — усе.
   - Паролі передайте людям особисто.
3. **Довідники → Підписанти.** Додайте тих, хто підписує накази (директор, заступники).
4. **Налаштування → «Що бачать без входу»** [рекомендовано переглянути]: «Повний» (основні накази зі сканами бачить кожен у мережі), «Без сканів» (накази видно, скани — після входу) або «Закрито».
5. **Імпорт з Excel/CSV** [за потреби] — якщо є старий реєстр в Excel. Формат колонок — у вікні імпорту.

✅ **Перевірка:** вийдіть (меню з вашим ім'ям → «Вийти») і увійдіть під одним із співробітників — він має бачити свої реєстри й кнопку «+ Новий наказ».

## 5. Перевірити основні функції [рекомендовано]

Під адміністратором:
1. **«+ Новий наказ»** → заповніть назву, прикріпіть PDF (кнопкою або перетягніть файл у вікно) → «Зберегти».
2. Прикріпіть до будь-якого наказу **Word-файл**, клацніть по його значку в таблиці — праворуч має з'явитися перегляд (перший раз кілька секунд).
3. Видаліть тестовий наказ (знадобиться ваш пароль) і натисніть **«Повернути»** у повідомленні внизу — наказ має повернутися. Потім видаліть його знову, якщо він не потрібен.
4. **Довідка** (кнопка угорі) — інструкції для кожної ролі; дайте працівникам знати, що вона є.

## 6. HTTPS — шифроване з'єднання [за потреби]

> Потрібен Docker Compose **2.24 або новіший** (перевірити: `docker compose version`). `install.sh` ставить свіжий Docker, тож якщо ви встановлювали за цією інструкцією — усе гаразд. Якщо Docker на сервері старіший (наприклад, з репозиторію Debian), `update.sh` підкаже, як оновити.

Потрібно, якщо до мережі мають доступ сторонні (гостьовий Wi-Fi, спільна мережа з іншими установами) або буде доступ іззовні через VPN. У закритій офісній мережі можна не вмикати.

1. На сервері відкрийте файл налаштувань:
   ```bash
   nano /opt/nakazy/.env
   ```
   допишіть у кінець два рядки (адреса — ваша):
   ```
   COMPOSE_FILE=docker-compose.yml:docker-compose.https.yml
   SITE_ADDRESS=192.168.1.100
   ```
   збережіть: `Ctrl+O`, `Enter`, вийти: `Ctrl+X`.
2. Застосуйте:
   ```bash
   cd /opt/nakazy && ./update.sh
   ```
3. Відкрийте `https://192.168.1.100`. Браузер попередить «Підключення не захищене» — це нормально до наступного кроку. Натисніть «Додатково» → «Перейти на сайт», увійдіть.
4. **Адміністрування → Налаштування → «Сертифікат HTTPS» → «Завантажити сертифікат».** Встановіть його на **кожен** комп'ютер, з якого відкривають програму:
   - двічі клацніть файл `nakazy-ca.crt` → «Установить сертификат» → «Локальный компьютер» → «Поместить все сертификаты в следующее хранилище» → «Обзор» → **«Доверенные корневые центры сертификации»** → ОК → Далее → Готово;
   - або в командному рядку від імені адміністратора: `certutil -addstore -f Root nakazy-ca.crt`;
   - повністю закрийте й знову відкрийте браузер.

✅ **Перевірка:** `https://192.168.1.100` відкривається із замком, без попереджень. Старі посилання `http://…` самі переводять на HTTPS.

> Папку `/opt/nakazy/caddy` (там сертифікат) зберігайте в резервних копіях разом із `data` — інакше після відновлення сертифікат доведеться ставити на всі комп'ютери заново. Копія в Google Диск (наступний крок) робить це сама.

## 7. Копія в Google Диск [рекомендовано]

Щодня в заданий час сервер робить **зашифровану** копію бази й сканів у Google Диск; з неї можна відновити все на новому сервері. Потрібен Google-акаунт (безкоштовно — 15 ГБ; розмір ваших даних показує `du -sh /opt/nakazy/data`).

1. На сервері:
   ```bash
   cd /opt/nakazy && ./backup_gdrive.sh --setup
   ```
2. Майстер попросить **на своєму комп'ютері** відкрити командний рядок (`Win+R` → `cmd`) і виконати команду на кшталт
   ```
   ssh -L 53682:localhost:53682 admin@192.168.1.100
   ```
   увійти паролем свого користувача (`admin`) і **не закривати** це вікно. Потім — відкрити в браузері посилання `http://127.0.0.1:53682/auth?state=…`, яке покаже майстер, увійти в Google-акаунт для копій і натиснути «Дозволити».
3. Майстер покаже **два ключі шифрування** і збереже їх у файл `/root/nakazy-backup-KEYS.txt`. ⚠ **Без цих ключів копію відновити неможливо.** У файлі також є **ключ доступу до вашого Google Диска** — поводьтеся з ним як із паролем.
   - Якщо ви заходите в WinSCP під root — просто заберіть файл з `/root` на свій комп'ютер.
   - Якщо під звичайним користувачем — у другому вікні (під root) тимчасово скопіюйте його у свою домашню папку:
     ```bash
     cp /root/nakazy-backup-KEYS.txt /home/admin/ && chown admin /home/admin/nakazy-backup-KEYS.txt
     ```
     заберіть через WinSCP і **одразу видаліть цю копію**:
     ```bash
     rm /home/admin/nakazy-backup-KEYS.txt
     ```
   - Збережіть файл **не на сервері** (флешка в сейфі, менеджер паролів керівника), не пересилайте його поштою чи в месенджерах. Після цього введіть у майстрі «так».
   - Оригінал у `/root` можна видалити (`rm /root/nakazy-backup-KEYS.txt`): копії працюватимуть і без нього. Знадобиться — майстер `--setup` відтворить файл знову.
4. Майстер зробить першу копію (перший раз — довго, вивантажуються всі скани) і ввімкне автоматичний розклад.
5. Далі все — у браузері: **Адміністрування → Налаштування → «Копія в Google Диск»**: час щоденної копії (за замовчуванням 02:30), «Зробити копію зараз», стан і журнал.

✅ **Перевірка:** у «Налаштуваннях» стан **«✓ Працює»** зі свіжою датою.

> **Якщо вхід у Google зірвався** (браузер не зміг відкрити посилання, не встигли натиснути «Дозволити» тощо) — нічого прибирати вручну не треба: просто запустіть `./backup_gdrive.sh --setup` ще раз. Майстер сам перевірить підключення, видалить недороблене й підключить заново; уже створене шифрування й ключі збережуться. Найчастіша причина збою — закрите вікно з `ssh -L 53682:…` або посилання, відкрите в браузері на сервері, а не на своєму комп'ютері.

## 8. Перевірити відновлення [рекомендовано, один раз]

Копія корисна лише тоді, коли з неї вдається відновитись. Найкраще — на **окремій тестовій** віртуальній машині: встановіть програму за кроками 1–2, встановіть rclone (`apt-get install -y rclone`), скопіюйте в `/root/.config/rclone/rclone.conf` частину файлу ключів після рядка «Повні налаштування rclone» і виконайте:
```bash
cd /opt/nakazy && ./backup_gdrive.sh --restore
```
✅ **Перевірка:** на тестовій машині видно ті самі накази й скани, вхід — тими самими паролями.

## Щоденна робота й оновлення

- Сервер можна перезавантажувати — програма запускається сама.
- **Оновлення програми** (коли отримаєте новий `nakazy.zip`): покладіть його через WinSCP у свою домашню папку, зайдіть на сервер, `su -`, і виконайте
  ```bash
  mv /home/admin/nakazy.zip /opt/ && cd /opt && unzip -o nakazy.zip && cd nakazy && ./update.sh
  ```
  Скрипт зробить копію даних, оновить програму й перевірить її. Якщо нова версія не запуститься — сам поверне і дані, і попередню версію. Що змінилось — «Довідка → Історія змін».
- **Резервні копії** без хмари: папка `/opt/nakazy/data` (і `/opt/nakazy/caddy` з HTTPS) — найпростіше, щоб її захоплювала копія всієї віртуальної машини.
- **Журнал дій** (хто що змінив) і **Кошик** (видалене за 30 днів) — у меню «Адміністрування».

## Якщо щось пішло не так

| Ситуація | Що робити |
|---|---|
| `install.sh` довго «стоїть» на завантаженні | зачекайте: перша збірка завантажує ~1 ГБ. Якщо понад 30 хв без змін — перевірте інтернет на сервері (`ping -c3 deb.debian.org`) |
| Сайт не відкривається з інших комп'ютерів | на сервері `cd /opt/nakazy && docker compose ps` — має бути `Up`. Перевірте, що адреса правильна (`hostname -I`) і що комп'ютер у тій самій мережі |
| Забули пароль адміністратора | команда в README, розділ «Типові проблеми» |
| Не відкривається перегляд Word/Excel | перші хвилини після запуску повторіть; файл завжди можна завантажити кнопкою «⬇» |
| Будь-яка інша помилка | на сервері `cd /opt/nakazy && docker compose logs --tail 50` — надішліть вивід тому, хто дав вам архів |

Повний довідник по всіх можливостях і налаштуваннях — у файлі **`README.md`**. Інструкції для працівників — у програмі, кнопка **«Довідка»**.
