# Реєстр наказів, версія 1.10

Веб-застосунок для реєстрації наказів у локальній мережі: основний реєстр і кадрові реєстри, скани (PDF, Word, Excel, презентації, зображення, архіви ZIP/7Z/RAR) з переглядом у браузері, ролі, зв'язки між наказами («скасовує», «вносить зміни»), кошик на 30 днів, журнал дій, щотижнева перевірка пропущених номерів і наказів без сканів, довідка, історія версій. Працює в Docker, дані лежать в одній папці `data/`. Інтернет потрібен лише для встановлення, оновлень і копії в Google Диск.

Усе, що потрібно для розгортання, є в цьому архіві. **Покрокова інструкція встановлення для адміністратора — у файлі `INSTALL.md`** (з чистого Debian до робочої програми, з перевірками). Нижче — довідник по всіх можливостях.

---

## 1. Що потрібно

- Сервер або віртуальна машина з Linux (працює на мінімальному Debian 13; підійде також Ubuntu). Windows і macOS підходять для пробного запуску з Docker Desktop.
- 2 ГБ оперативної пам'яті, 3 ГБ вільного місця для програми (з LibreOffice) плюс місце під скани (приблизно розмір ваших файлів).
- Статична IP-адреса в локальній мережі.
- Інтернет на час встановлення й оновлень (завантажуються Python, LibreOffice, шрифти) і для копії в Google Диск. Для щоденної роботи інтернет не потрібен.
- Вільний порт 80 (інший порт можна задати, див. розділ 5).

## 2. Встановлення з нуля (5 хвилин)

1. Скопіюйте архів `nakazy.zip` на сервер у папку `/opt` і розпакуйте (команди тут і далі — від root: `su -` або через `sudo`; у Debian вхід по SSH одразу під root заборонений, тож заходьте звичайним користувачем — покроково в `INSTALL.md`):
   ```bash
   apt-get update && apt-get install -y unzip      # якщо unzip немає
   cd /opt && unzip nakazy.zip && cd nakazy
   ```
   Програма житиме в `/opt/nakazy`, дані — в `/opt/nakazy/data`.
2. Запустіть встановлення:
   ```bash
   chmod +x install.sh update.sh   # зазвичай права вже є в архіві
   ./install.sh
   ```
   Скрипт сам встановить Docker (якщо його немає), збере програму, запустить і перевірить, що вона відповідає. Перший раз це триває кілька хвилин. У кінці він надрукує адресу, наприклад `http://192.168.1.100`.
3. Відкрийте цю адресу в браузері.
4. Натисніть «Увійти», оберіть **Адміністратор** і введіть пароль, який надрукував `install.sh` (він же у файлі `.env`). **Одразу змініть пароль** на свій (меню з вашим ім'ям → «Змінити пароль»).
5. «Адміністрування → Довідники»: додайте співробітників (галочки ролей і пароль), підписантів; на вкладці «Реєстри» перейменуйте реєстри під свою номенклатуру справ і задайте суфікси номерів (за замовчуванням є «Основна діяльність» і один кадровий «Кадрові» із суфіксом «-к»). Описи ролей і всіх дій є в кнопці «Довідка» угорі.

Якщо Docker уже встановлений, можна без скрипта:
```bash
mkdir -p data && docker compose up -d --build
```

Програма сама запускається після перезавантаження сервера (`restart: unless-stopped`).

## 3. Ролі

| Хто | Що бачить | Що може |
|---|---|---|
| Без входу | Основні накази (або ті самі накази без сканів, або нічого — обирає адміністратор) | Лише перегляд, пошук і фільтри |
| Переглядач | Усі реєстри | Лише перегляд (для головного бухгалтера, керівництва) |
| Секретар | Усі реєстри | Створює, редагує, видаляє **основні** накази |
| Кадровик | Усі реєстри | Створює, редагує, видаляє **кадрові** накази |
| Адміністратор | Усе | Усе, а також довідники, імпорт, експорт, резервна копія |

Одна людина може мати кілька ролей. Роль без пароля не працює. Вхід: вибір імені зі списку і пароль. Видалення наказу вимагає пароль того, хто видаляє; видалений наказ 30 днів лежить у кошику (відновлює адміністратор). Усі зміни записуються в журнал дій (бачить адміністратор).

## 4. Де що лежить і резервні копії

Усі ваші дані лежать у папці **`/opt/nakazy/data/`** поряд з `docker-compose.yml`. Саму програму (образ Docker) можна безпечно перезбирати: дані не змінюються.

| Шлях | Що там |
|---|---|
| `data/orders.db` | база наказів, довідники, користувачі, журнал дій, кошик |
| `data/uploads/РІК/МІСЯЦЬ/` | прикріплені файли |
| `data/backups/` | копії бази, які програма робить перед змінами структури |
| `data/cache/` | кеш перегляду (можна видаляти, відновиться сам) |
| `backups/data_ДАТА_ЧАС/` | копії всієї `data/`, які робить `update.sh` (7 останніх) |
| `data/secret.key` | ключ сеансів входу (якщо видалити, усім доведеться увійти знову) |

**Що копіювати:** папку `data/` повністю. Автоматична зашифрована копія в Google Диск — розділ 14. Найпростіше — щоб її захоплювала нічна копія всієї віртуальної машини. Якщо ввімкнено HTTPS, копіюйте також папку `caddy/` (у ній кореневий сертифікат: без неї після відновлення сертифікат доведеться ставити на комп'ютери заново). Додатково адміністратор може завантажити копію бази з меню «Адміністрування → Резервна копія бази» і експорт у CSV.

**Як перевірити, що копія придатна:** розгорніть копію як окрему тестову машину (не поверх робочої), відкрийте програму, перевірте, що накази й скани на місці. Для бази: 
```bash
docker compose exec -u app nakazy python -c "import sqlite3;c=sqlite3.connect('/data/orders.db');print(c.execute('PRAGMA integrity_check').fetchone(), c.execute('SELECT COUNT(*) FROM orders').fetchone())"
```
(має бути `ok` і кількість наказів).

## 5. Налаштування (файл `.env`)

Необов'язково. Скопіюйте шаблон і розкоментуйте потрібне:
```bash
cp .env.example .env
nano .env
```
| Змінна | Що робить | За замовчуванням |
|---|---|---|
| `HTTP_PORT` | зовнішній порт сайту | `80` |
| `TIMEZONE` | часовий пояс | `Europe/Kyiv` |
| `INITIAL_ADMIN_PASSWORD` | пароль адміністратора на **першому** запуску (порожня база) | на новій установці `install.sh` генерує випадковий і дописує сюди |
| `COMPOSE_FILE`, `SITE_ADDRESS`, `HTTPS_PORT`, `CADDY_TLS` | увімкнення HTTPS, див. розділ 11 | вимкнено |

Після змін у папці `/opt/nakazy`: `docker compose up -d`.

## 6. Оновлення програми без втрати даних

1. Покладіть новий `nakazy.zip` у `/opt` (поверх старого архіву).
2. Розпакуйте його поверх папки програми й запустіть оновлення однією командою:
   ```bash
   cd /opt && unzip -o nakazy.zip && cd nakazy && ./update.sh
   ```
   Папки `data/`, `backups/` і файл `.env` не перезаписуються, бо їх немає в архіві.
Скрипт спершу збирає нову версію (стара в цей час працює), потім на кілька секунд зупиняє програму й робить копію `data/` у `backups/` (зберігає 7 останніх; скани жорсткими посиланнями, тож копії майже не займають місця), запускає нову версію, перевіряє, що вона відповідає, а якщо ні — сам повертає і дані, і попередню версію програми (вона знову працює, як до оновлення). Зміни структури бази застосовуються автоматично. Якщо сторінка в браузері виглядає по-старому, натисніть Ctrl+F5. Що змінилось, адміністратор бачить у «Довідка → Історія змін».

## 7. Перенесення на інший сервер

1. На старому сервері: `cd /opt/nakazy && docker compose down` (необов'язково, але надійніше).
2. Скопіюйте на новий сервер всю папку `nakazy/` разом з `data/`, `.env` і (якщо є) `caddy/` (наприклад, `scp -r` або архівом).
3. На новому сервері (у ту саму папку `/opt/nakazy`): `cd /opt/nakazy && ./install.sh`. Скрипт підхопить наявну папку `data/`, і всі накази, користувачі й файли будуть на місці.
4. Змініть IP в адресі для користувачів (або перенесіть старий IP на новий сервер).

## 8. Відновлення з копії

```bash
cd /opt/nakazy
docker compose down
mv data data_old                         # на всяк випадок не видаляємо
cp -a backups/data_РІК-МІС-ДЕНЬ_ЧАС data  # або розпакуйте свою копію папки data
docker compose up -d
```

## 9. Команди на кожен день

Виконуються в папці `/opt/nakazy`:
```bash
docker compose ps                    # чи працює
docker compose logs --tail 50 nakazy # журнал
docker compose restart               # перезапуск
docker compose down                  # зупинка (дані лишаються)
docker compose up -d                 # запуск
```

## 10. Типові проблеми

| Проблема | Що робити |
|---|---|
| Сайт не відкривається | `docker compose ps` (чи `Up`), `docker compose logs --tail 50` (з HTTPS дивіться й журнал `nakazy-caddy`). Перевірте IP і брандмауер: порт 80 має бути відкритий у локальній мережі. |
| «port is already allocated» | порт 80 зайнятий: задайте `HTTP_PORT=8080` у `.env` і виконайте `docker compose up -d`. Адреса тоді `http://IP:8080`. |
| Не відкривається перегляд Word/Excel | перші секунди після запуску LibreOffice завантажується; повторіть. Файл можна завжди завантажити кнопкою «⬇». |
| Забули пароль адміністратора | виконайте: `docker compose exec -u app nakazy python -c "import sqlite3,werkzeug.security as w;c=sqlite3.connect('/data/orders.db');c.execute(\"UPDATE employees SET password_hash=?,must_change=1 WHERE name='Адміністратор'\",(w.generate_password_hash('admin'),));c.commit()"` — пароль стане `admin` (змініть після входу). Спрацює, якщо службовий запис адміністратора не перейменовано. |
| «attempt to write a readonly database» | хтось виконав команду в контейнері від root. Виконайте `docker compose restart` — програма сама поверне права на папку `data/`. Команди в контейнері запускайте з `-u app`, як у цьому README. |
| Браузер пише «Підключення не захищене» (з HTTPS) | на цьому комп'ютері не встановлено сертифікат `nakazy-ca.crt`, див. розділ 11. Або сайт відкрито не за тією адресою, що в `SITE_ADDRESS`. |
| Chrome сам перекидає на `https://`, хоча HTTPS вимкнено | браузер запам'ятав переадресацію від старішої версії чи іншого сервера: `Ctrl+Shift+Delete` → «Зображення й файли в кеші» → «Видалити», або відкрийте в анонімному вікні. |
| Закінчилось місце | `df -h`; старі копії в `backups/` і `data/backups/` можна видалити, `data/cache/` теж. |

## 11. Безпека

### Що вже є
- Паролі зберігаються як хеші, мінімальна довжина нового пароля — 8 символів. Сеанс входу діє 12 годин; після зміни пароля інші сеанси користувача завершуються. Після 8 невдалих спроб вхід блокується на 2 хвилини (подія записується в журнал дій).
- На новій установці пароль адміністратора випадковий (не `admin`).
- Програма в контейнері працює не від root. Журнали Docker обмежені (до 30 МБ).
- Сторінка не виконує сторонніх скриптів і не відкривається всередині чужих сайтів; зміни даних приймаються лише зі сторінки самої програми (захист від CSRF). Вкладені HTML і SVG-файли в браузері не виконуються (лише завантаження).
- Видалене потрапляє в кошик на 30 днів, усі дії записуються в журнал (Адміністрування → Журнал дій).
- Скрипт копії в хмару (працює від root) не пише у файли папки програми напряму, тож навіть зламана програма не змогла б через нього змінити системні файли.

### Що налаштувати під свою мережу
| Ваша мережа | Що зробити |
|---|---|
| Закрита: лише працівники, Wi-Fi із паролем тільки для своїх | достатньо того, що є. HTTPS — за бажанням. |
| Є гостьовий Wi-Fi, спільна мережа з іншими установами, підрядники | увімкніть **HTTPS** (нижче) і розгляньте обмеження доступу без входу. |
| Потрібен доступ іззовні (з дому, з філії) | лише через VPN до локальної мережі, і обов'язково з HTTPS. **Не відкривайте порт програми в інтернет напряму.** |

**Доступ без входу** (Адміністрування → Налаштування): «Повний» — основний реєстр і скани видно всім у мережі (за замовчуванням); «Без сканів» — накази видно повністю, скани — після входу; «Закрито» — без входу нічого не видно. Кадрові реєстри без входу не видно ніколи. Тим, хто має бачити закрите, дайте роль «Переглядач» (можна один спільний запис на кількох).

### HTTPS
Перед програмою стає Caddy (окремий контейнер), він шифрує з'єднання. Потрібен інтернет на першому запуску (завантажується образ Caddy) і Docker Compose 2.24 або новіший (`docker compose version`; `install.sh` ставить свіжий).

1. У файлі `.env` додайте (IP чи ім'я — те, за яким користувачі відкривають сайт):
   ```
   COMPOSE_FILE=docker-compose.yml:docker-compose.https.yml
   SITE_ADDRESS=192.168.1.100
   ```
   Інший порт HTTPS: `HTTPS_PORT=8443`. Порт 443 має бути відкритий у брандмауері сервера.
2. Застосуйте: `cd /opt/nakazy && ./update.sh` (або `docker compose up -d`).
3. Сайт тепер: `https://192.168.1.100`. Адреса `http://…` сама переводить на HTTPS.
4. **Сертифікат на кожен комп'ютер (один раз).** Без домену Caddy видає власний сертифікат, і браузер довірятиме йому лише після встановлення кореневого сертифіката:
   - **перший комп'ютер (адміністратора):** відкрийте `http://192.168.1.100/nakazy-ca.crt` — завантажиться `nakazy-ca.crt`. Це посилання без входу працює **лише до зміни початкового пароля адміністратора** (того, що надрукував `install.sh`);
   - **решта комп'ютерів:** адміністратор завантажує сертифікат у програмі: «Адміністрування → Налаштування → Сертифікат HTTPS». Там же відбиток для звірки;
   - Windows: двічі клацніть файл → «Установить сертификат / Інсталювати сертифікат» → «Локальный компьютер / Локальний комп'ютер» → «Поместить все сертификаты в следующее хранилище» → «Доверенные корневые центры сертификации / Довірені кореневі центри сертифікації» → Готово. Або від імені адміністратора: `certutil -addstore -f Root nakazy-ca.crt`;
   - перезапустіть браузер. Chrome і Edge беруть сертифікат із Windows; Firefox — теж (якщо ні: `about:config` → `security.enterprise_roots.enabled` = `true`).
   - Якщо HTTPS вмикаєте на сервері, де пароль адміністратора вже змінено: на першому комп'ютері відкрийте `https://…`, у попередженні браузера оберіть «Додатково → Перейти на сайт», увійдіть і завантажте сертифікат у налаштуваннях.

   Сертифікат дійсний 10 років і зберігається в папці `caddy/` — копіюйте її разом із `data/`.
5. Якщо сервер має справжній домен, доступний з інтернету, можна взяти сертифікат Let's Encrypt (тоді на комп'ютери нічого ставити не треба): `SITE_ADDRESS=nakazy.приклад.ua` і `CADDY_TLS=ваш@email`.

Вимкнути HTTPS: приберіть рядок `COMPOSE_FILE` з `.env` і виконайте `docker compose up -d --remove-orphans`.

## 13. Імпорт з Excel/CSV

Адміністратор → «Імпорт з Excel/CSV». Файл .xlsx (читається перший аркуш) або .csv; старий .xls збережіть як .xlsx. Колонки (укр. і рос. заголовки): Номер, Дата, Реєстр (або Тип/Вид: «основна» чи індекс кадрового, як на вкладці реєстру), Назва/Зміст, Хто створив (кілька через «;»), Хто підписав, Статус («резерв», «втратив чинність» / «скасовано»). Обов'язкові — Дата й Назва (для резерву назва необов'язкова). Номер лише з цифр отримує суфікс реєстру. Нові ПІП автоматично потрапляють у довідники (без ролей). Повторний імпорт безпечний.

## 14. Копія в Google Диск (необов'язково)

Щодня в заданий час сервер сам робить **зашифровану** копію в Google Диск: базу (окремий файл на кожен день, 30 днів), скани (лише нові й змінені; видалені ще 30 днів лежать в окремій папці), файл `.env` і сертифікати HTTPS. Шифрування — на самому сервері, тож на Диску лежать нечитабельні файли: без пароля шифрування їх не відкриє ні Google, ні той, хто отримає доступ до акаунта. Замість Google Диска можна взяти будь-яке сховище, яке підтримує rclone (OneDrive, Dropbox, інший сервер по SFTP тощо).

**Що потрібно:** Google-акаунт з місцем під ваші дані (розмір покаже `du -sh /opt/nakazy/data`; безкоштовно — 15 ГБ) і комп'ютер із браузером для одноразового підключення акаунта.

### Налаштування (один раз, ~10 хвилин)
На сервері:
```bash
cd /opt/nakazy && ./backup_gdrive.sh --setup
```
Майстер сам встановить rclone, підключить Google Диск, налаштує шифрування, зробить першу копію й увімкне автоматичний запуск. **Далі все керується з програми** (Адміністрування → Налаштування → «Копія в Google Диск»): час щоденної копії (за замовчуванням 02:30), вимкнення, кнопка «Зробити копію зараз», стан і журнал останньої копії. Від вас при налаштуванні потрібно лише дві речі:

1. **Увійти в Google** (один раз). Майстер попросить на своєму комп'ютері відкрити командний рядок (`Win+R` → `cmd`) і виконати `ssh -L 53682:localhost:53682 ваш_логін@IP-сервера` (вікно не закривати), а потім відкрити в браузері посилання, яке покаже майстер, увійти в Google-акаунт для копій і натиснути «Дозволити». Майстер просить доступ лише до файлів, які створить сам, а не до всього Диска.
2. **Зберегти ключі шифрування.** Майстер покаже два паролі й збереже їх (разом із налаштуваннями) у файл `/root/nakazy-backup-KEYS.txt`. Заберіть цей файл на свій комп'ютер (WinSCP; спершу скопіюйте його з `/root` у свою домашню папку — покроково в `INSTALL.md`) і зберігайте **не на сервері**: флешка в сейфі, менеджер паролів керівника. ⚠ **Без цих ключів відновити копію неможливо.**

Перша копія вивантажує всі скани й може тривати довго; далі щодня — лише нові.

Як це працює: сервер кожні 5 хвилин перевіряє розклад і запити з програми (таймер systemd `nakazy-backup.timer`). Тому «Зробити копію зараз» починається протягом 5 хвилин, а якщо в заданий час сервер був вимкнений — копія зробиться після ввімкнення того ж дня.

Якщо копія не вдалася або не робилася понад 2 дні — адміністратор побачить це в «Перевірці». Журнал на сервері: `journalctl -u nakazy-backup -n 50`.

Налаштування в `.env` (необов'язково): `BACKUP_REMOTE=nakazy-crypt:` — куди копіювати, `BACKUP_KEEP_DAYS=30` — скільки днів зберігати копії бази й видалені скани.

### Відновлення з Диска
```bash
cd /opt/nakazy
./backup_gdrive.sh --list                 # які дні є
./backup_gdrive.sh --restore              # найновіша копія
./backup_gdrive.sh --restore 2026-10-18   # або за потрібний день
```
Скрипт спитає підтвердження, зупинить програму, відкладе поточну папку `data` у `data_before_restore_…` (нічого не видаляє), завантажить базу за вибраний день і скани, запустить програму. Скани відновлюються в останньому стані.

**На новому сервері** (старий зламався): встановіть програму (`./install.sh`), встановіть rclone (`apt-get install -y rclone`), з файлу ключів `nakazy-backup-KEYS.txt` скопіюйте частину після рядка «Повні налаштування rclone» у файл `/root/.config/rclone/rclone.conf`, потім `./backup_gdrive.sh --restore`. Разом із даними відновляться налаштування `.env` (порт, HTTPS) і сертифікати HTTPS, тож сертифікат на комп'ютери ставити заново не треба. Далі один раз виконайте `./backup_gdrive.sh --timer`, щоб копії знову робились автоматично.

**Перевірте відновлення заздалегідь** — на тестовій машині, не на робочій: копія корисна лише тоді, коли з неї точно вдається відновитись.
